# Six-way source spawn selection audit

This passive lifecycle audit found a concrete initial-entry/replay mismatch on both recovered maps. No original Director/Lingo runtime or GPU was executed.

Both [Barrack explore](<../2026-09-30/director-script-extraction/barrack/casts/parents/BehaviorScript 32 - explore.ls>) and [Woodland explore](<../2026-09-30/director-script-extraction/woodland/casts/parents/BehaviorScript 32 - explore.ls>), lines43–53, build six position/rotation pairs, choose `random(vstarts.count)`, and construct the local goody from the selected pair. Neither selection examines other actors or threats. [Endgame](<../2026-09-30/director-script-extraction/barrack/casts/parents/BehaviorScript 34 - endgame.ls>), lines16–25, returns replay through resetall and lobby; a new gameplay entry rebuilds the level and samples again.

The pre-correction copy did not implement that choice. Game.restartState always used spawn index0 and its rotation. MatchRoom.chooseSpawn used the first/cycled start in an empty room and the position farthest from living peers otherwise. Its source initialTransform did pair the chosen position with its recovered rotation; position selection was the defect. The earlier lifecycle report's claim that local six-way random selection already agreed was therefore too strong.

[Shared originalSpawnIndex](../../../shared/originalSpawnRules.ts) now maps a valid uniform fraction to one of six equal intervals, returning a zero-based index. It rejects invalid counts and fractions outside finite `[0,1)`. [Authority](../../../server/match-room.ts) uses this helper for default recovered scenes. Explicit custom starts and archived Winter preserve their authored spawn policy. Root integration owns the solo restartState change and its actual Game/browser verification; this audit's focused checks do not establish that integration independently.

[Authority tests](../../../server/original-spawn-selection.test.ts) select all six pairs while previously joined players remain alive, then select the same occupied start again. This specifically proves that a living threat does not redirect selection. They also preserve custom-start behavior on Barrack, Woodland and Winter. The existing geometry sweep fixture now explicitly starts at its intended source position instead of depending on the production first-spawn policy. The helper's two tests cover interval boundaries, endpoints and invalid inputs.

Focused authority verification passes25 tests across original-spawn-selection, original-scene and session-lifecycle; helper verification passes2 tests; server TypeScript checking passes. Logs are `/tmp/source-spawn-authority-tests.log`, `/tmp/source-spawn-rules-tests.log` and `/tmp/source-spawn-authority-types.log`. These are implementation checks, not native PRNG-sequence or exact runtime measurements. Source dummy initialization and the copy's existing terrain-settled position adapter are unchanged.

G05 remains open: this correction establishes a particular fresh-life spawn rule, not complete original disconnect delivery, observer actor lifetime, replay raster/timing or historical relay-server room reset policy.
