# Source explosives after owner departure

Barrack and Woodland authority now retains received grenade/rocket actors and active blasts after their owner dies, leaves, disconnects or expires from the resume table. The stored launch name survives into explosion, damage, death feedback and results. An absent owner no longer suppresses five-point blast callbacks or victim death/drop bookkeeping. Archived Winter retains its departure cleanup.

## Source and implementation

The [passive source audit](ORIGINAL_DEPARTED_OWNER_EXPLOSIVES_AUDIT.md) pins both editions’ grenade/rocket/bangs actors and MUS/goody handlers. Explosive actors retain `pname`; bangs applies five damage on each of sixteen qualifying callbacks independently of whether getplayer resolves an actor. That lookup supplies directional feedback, while damage and local hurt audio still occur without it. Death/replay clears the departing client’s own actors, rather than resetting surviving clients’ worlds.

[Authority](../../../server/match-room.ts) captures immutable ID/name when it accepts a source launch. Projectile event/snapshot clones preserve that name. Source departure cleanup retains these bounded actors; their existing physics, fuse, blast lifetime and target eligibility continue. Lethal bookkeeping can use detached attribution without assigning the victim as killer, retaining a mutable removed player, or extending a resume credential. It still creates one persistent source weapon drop, cancels reload/movement authorization and publishes terminal authority. Empty-room retirement remains transport cleanup, rather than a persistent empty-world simulation.

Protocol11 adds optional `attackerName` to projectile/blast snapshots, explosive event data and explosive damage causes. The browser validates bounded callsign text and preserves it without normalization. Accepted source launches always supply it; explicit legacy fixtures and Winter can omit it. Unknown legacy attribution preserves omission instead of emitting an invalid empty name. No client launch claim can choose authority’s owner name or score recipients.

Source MUS score receipt is by name: every connected living client whose name ASCII-matches the stored owner name receives30, excluding every name matching the victim/sender. This includes a fresh same-name session and multiple matching living receivers; departed/dead clients receive no invented points. The [shared ASCII comparator](../../../shared/originalNameComparison.ts) follows the Director operator evidence in the [Cowardice audit](ORIGINAL_COWARDICE_LIFECYCLE_AUDIT.md), while leaving native extended-character tables unimplemented. A validated `sourceScoreRecipients` array transmits exact authoritative counters separately from immutable original launcher identity. Fresh same-name recipients gain score without a fabricated shot hitmarker or previous-life movement ownership.

[Game](../../../src/game.ts) uses the stored source name for death/results/remote feedback. Hurt direction checks own name first, then a current living matching remote. Absent actors provide no invented direction or fallback to the blast origin. Existing local hurt audio and signed source health remain active. Labels use plain text; a player name cannot inject markup. Missing-name legacy and Winter routes retain their existing behavior.

## Verification

[New authority cases](../../../server/original-departed-explosives.test.ts) cover both maps/weapons and explicit leave/suspension, real accepted fuses, event/snapshot name preservation, remaining blast callbacks, lethal signed health, exactly one drop, live/dead/detached/fresh/duplicate-name score receipt, victim-name exclusion, resume/session expiry, old-life movement cancellation and unchanged Winter cleanup. Controlled damage fixtures detonate an accepted projectile at a known victim eye; eight fuse cases run its actual source trajectory/lifetime.

[Actual Game cases](../../../src/originalDepartedExplosivesGameplay.test.ts) cover absent-owner hurt/audio/direction, retained result/feedback text, safe markup text, local-first ASCII direction lookup, missing-name/Winter compatibility and exact recipient counters without fresh-session weapon credit. Network tests validate optional-name forwarding and malformed names/recipient arrays.

[Live browser cases](../../../e2e/original-departed-explosives.spec.ts) use two actual Game clients and an isolated real-socket MatchRoom/parser. A recovered spawn and a supported two-metre offset place them within blast range without overlapping bodies or automatic drop pickup; lethal cases seed60 health before welcome. A socket receipt triggers a delivered DOM Escape event through actual Game: either immediately after accepted projectile spawn or after the first victim blast damage. This selects the before/during edge without a browser IPC timing race; it is controlled test input, not proof of native physical-key timing. Assertions require departure/event order, preserved launch name/identity, sixteen actual5-damage callbacks for near blasts; upward before-departure RPG cases travel to their original fuse expiry and produce no distant damage, visible source atlas state, local hurt sample counts, lethal original-owner results, one victim drop and no page/server errors. Fixture setup changes neither production damage nor fuse/callback handling.

The initial full unit run found the protocol-version fixture still pinned to10; it now pins11. The first ten browser cases caught an actual serializer omission: cloneProjectile dropped the internally stored name. Corrected unit assertions now inspect emitted events and getSnapshot as well as internal state. The second run passed all seven existing regressions and two new cases, but exposed fixture assumptions: overlapping bodies caused real contact movement and pickup score; downward RPGs naturally detonated before departure; default polling missed short atlas presentation;20 health could end the victim before the owner left. The corrected fixture separates supported spawns, uses upward flight for before-departure RPG expiry, observes short-lived atlas state at20ms intervals, and seeds60 health only for lethal remaining-callback cases. Production damage, contact physics, fuses, receipt limits and scoring assertions are unchanged. Initial failed logs/traces are retained. [Final validation](../../../artifacts/fidelity-review/2026-10-01/current/source-departed-validation.json) records1,272 client/shared tests across122 files plus398 server tests across24 files (1,670 total), both TypeScript builds, production build, focused E2E TypeScript and seventeen unique affected browser cases passing across recorded runs. All ten corrected departure cases pass in one invocation; all seven existing regressions pass in the preceding combined invocation. This is not a claim that the initially failing combined run was all-green. Near cases observe sixteen damage events and health20; upward before-departure RPGs expire without distant damage. Lethal60-health cases observe twelve Barrack/thirteen Woodland damage events, actual OWNER results, zero invented score and one victim drop. Both lethal result captures were inspected.

## Limits and checklist

Original Director, Flash, ActionScript and MultiUser execution remain unperformed. Native callback birth/order, Havok response, mixing, case tables, duplicate-name service restrictions and original raster/time registration are unproved. The copy retains its current living/connected actor direction eligibility and30-second reconnect adapter; native remote actors can briefly remain after death/departure and time out at−450 callbacks. This correction does not equate those callbacks to an original wall-clock timeout. Ordinary lethal source damage still ends the local life from its damaged event; authority emits killed/drop before processing the resulting leave, but the departing victim does not wait to consume killed as the Cowardice route does.

Source single-life rooms continue without a frag-limit ending, consistent with inspected source; unrecovered publisher administration remains unknown. [Original result-frame54 artwork](ORIGINAL_RESULT_FRAME54_AUDIT.md) is located but its passive exporter/replacement remains outstanding. Acceptance remains27/40 with all thirteen broader open points active.
