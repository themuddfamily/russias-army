## Source instructions and installed phase

The preserved [Barrack baddies script](../2026-09-30/director-script-extraction/barrack/casts/parents/ParentScript%208%20-%20baddies.ls) sets position below the remote eye, adds native yaw90, clears pitch, adds `speed.magnitude * 10` to animation time and subtracts1000 once only when the result exceeds1000. Shooting assigns2000. Woodland has the corresponding handlers. Authority advances phase once per nominal source callback from accepted feet displacement converted back to source units, preserves it across reconnect and includes it in snapshots. Alive remotes render that transported phase rather than advancing an independent clock.

`baddies.die` initially assigns3000, then hands the actor to [fadeaway](../2026-09-30/director-script-extraction/barrack/casts/parents/ParentScript%209%20-%20fadeaway.ls). That separate actor starts a zero counter, advances it by8, samples `2400 + bon`, sinks the model and removes it above600. The copy transports the fadeaway sequence starting at2400; it does not reproduce the transient initial3000 assignment as a separately observable network frame. Dead remotes continue a monotonic local fade if room snapshots stop and ignore stale phase rewinds.

## Query and transport choices

The source [weaponry handler](../2026-09-30/director-script-extraction/barrack/casts/parents/ParentScript%206%20-%20weaponry.ls) requests the first detailed visible-model ray hit. The copy intersects front-facing posed GI triangles and the recovered world, retaining equal damage across hit locations. Native detailed-query sidedness remains unproved. The existing700-world-unit weapon query bound is an engineering limit above both decoded scene diagonals, not a recovered range rule. The CPU triangle helper uses a larger internal bound before weapon validation.

Authority retains at most32 accepted pose samples over300ms and captures them when a shot is registered. Rewind queries those discrete posed meshes, without swept capsules or interpolated solids filling limb gaps. This is a multiplayer adapter, not historical message-order proof. Independent actor histories can let an older nearer pose block a currently clear ray. Client hit requests still originate from predicted-eye selection, so an authority-valid ray can miss damage when the predicted client query selects no actor. Remote positions interpolate even while animation phase follows snapshots; live world placement need not match authority at the same instant. Held guns remain excluded from source target geometry; exclusion of the removed `gsmokes` branch's descendants is a native-engine inference documented in [hitscan rules](../2026-09-30/ORIGINAL_HITSCAN_RULES.md).

Real online checks exposed a gun-counter synchronization race. Source loadouts now acknowledge the exact processed shot ID, including rejection. The client permits one outstanding source shot, clears only its matching acknowledgement, and avoids advancing a restored gun counter through an earlier callback. Body/projectile callbacks still run. Reconnect and fresh spawn clear the pending shot and counter authority epoch. Protocol5 requires this acknowledgement contract; old protocol4 clients are rejected explicitly. One outstanding shot can limit firing to round-trip time and does not prove historical network cadence.

Source shots use the current authoritative eye for queries and broadcast origins. Reported origins remain finite and bounded to2.75 units; an unused chord to an old reported eye no longer rejects source shots against intervening geometry. Winter preserves its existing origin checks. This prevents the source query from depending on a stale predicted eye or accepting a spoofed query origin within the tolerance.
