# Convex projection iterator guard and rejected lazy-axis follow-up

A frozen vector list can expose a custom Symbol.iterator even when all indexed coordinates are ordinary frozen values. The recently integrated shape face-prefix projection cache assumed numeric prefix positions were the same axes traversed by spread/for-of. The [counterexample](../../../artifacts/fidelity-review/2026-10-02/current/lazy-edge-axis-trial/custom-iterator-counterexample.json) reproduces an incorrect wall hit: fraction0 with upward normal instead of the original fraction0.48325804314893833 with sideways normal. The original source, reproducible script and output are preserved.

[The corrected gate](../../../shared/originalConvexSweep.ts) permits the new shared face-axis cache only when shape vertices/normals/edge lists and triangle use ordinary Array.prototype iteration with no own iterator override and the retained builtin prototype iterator identity. Descriptor checks do not invoke iterator accessors. The existing immutable triangle-pair cache and generic eager arithmetic remain unchanged. No source motion, force, tolerance, event/solver cap, fuse or deadline is altered. The corrected counterexample matches the historical query exactly.

Four [new regressions](../../../shared/originalConvexIterator.test.ts) cover zero-yield frozen iterators, reordered axes with an actual tie, and mutable/frozen iterator accessor read sequences. The first focused run reports127passes and one test expectation failure: wall normal.z is the original−0, while the new fixture incorrectly expected+0. The exact initial test/log are preserved; the final assertion checks literal−0 with Object.is semantics intact. Final focused run passes128cases across10files. The production build passes. A128-callback actual Barrack sequence retains exact binary64 physical fields, snapshots and emitted messages across this guard correction. This is not universal/native/world proof.

The detached lazy edge-axis variant keeps eager preparation for generic inputs and defers cross products for standard immutable inputs. Expanded7,128queries match exactly. Seven alternating synthetic batches after the guard have baseline median277.156889ms versus lazy293.730971ms; the lazy variant is slower in four batches and is rejected. The pre-guard benchmark/source/results remain separate evidence. Earlier historical lazy-SAT failure is also acknowledged; no performance success is inferred from either phase.

Current production contains the iterator guard and prior face-axis sharing, but no lazy edge-axis code. The previous ramp near-deadline pass and two failing5-second Barrack server gates remain unresolved historical results; they are not rerun or relabelled by this correctness fix. The full client/shared suite and movement/lifecycle browser gates are likewise not rerun. Checklist acceptance stays28/40 and all original requirements remain in scope.

## Later admission based on authentic rejection workload

The mixed synthetic trial above remains a rejected result at its original scope. A subsequent [authentic query capture](ORIGINAL_LIVE_SAT_REJECTION_WORKLOAD.md) finds11,264actual Barrack sweeps, all misses, and a consistent speed benefit from deferring unused cross axes on those inputs. The final guarded lazy variant is now integrated after exact query/server parity and focused regression/build checks. This does not relabel the earlier mixed benchmark or prove speed for every workload.
