# Bounded fixed angular TOI refiner design

This is a design review only; no production changes or new browser/test runs accompany it. The retained [actual-pose audit](/root/russias-army/docs/research-evidence/2026-10-02/ORIGINAL_FIXED_ANGULAR_TOI_GEOMETRY_AUDIT.md) proves 51 absent grenade/floor events in seven final276 independent callback seeds. It does not establish a selected door defect or standalone runtime result.

## Private registration and result contract

Use a small shared module, for example `/root/russias-army/shared/originalFixedContactRefinement.ts`, with a module-private `WeakMap<object, Registration>`. Avoid attaching enumerable triangle metadata or callable functions to public contact objects, network state, callback captures or protocol payloads. A registration holds the selected immutable triangle's refiner closure, the selected model privately, and optionally an active-feature check. Weak keys keep ownership tied to existing hit lifetimes; world sweep memos already retain at most one contact per body.

Provide three bounded operations: register a returned hit, transfer its registration to a known local contact clone, and refine a registered hit at an actual full-hull pose. The refiner result is deliberately three-state:

- A genuine refreshed hit means the selected finite feature exists at the actual rotated pose. Return actual position, normal, depth and finite witnesses/patch.
- `null` means the known selected feature is absent at unchanged T, or its known door rigid body has been deleted. Do not respond or dispatch its handler.
- `undefined` means no supported registration/context exists. Preserve generic caller compatibility; do not classify unavailable custom geometry as absent.

The helper should take only the contact, actual pivot and actual oriented convex shape. The registered closure captures the exact sweep contact distance and immutable selected feature. It must not accept or manufacture a larger tolerance. Distinguish geometry admission from notification policy; raw stationary selected-feature queries do not use the separating-velocity filter.

## Scene implementation boundary

At `/root/russias-army/shared/originalSceneGeometry.ts:431`, keep the winning triangle reference when selecting the earliest frozen-hull hit. At `:447`, register the final returned hit after the existing adjoining-patch aggregation. Registering the intermediate hit loses metadata when `{...best}` creates the final object.

The refiner tests this exact finite triangle using the unchanged production stationary convex/triangle query at the actual pose. If genuine, regenerate witnesses using the refreshed normal and actual hull. Preserve the original finite adjoining-patch aggregation policy, coordinate allowances and deterministic candidate order at the current pose. A small extracted patch helper is reasonable only if old sweep results remain exact. Do not use a global closest stationary sweep as the selected-feature refiner: another finite triangle can win, and its presence does not validate the earlier candidate. Do not reuse earlier penetration, witness pairs or normal after actual rotation.

The response event retains its original positive fraction and consumed elapsed time. A stationary fresh hit's internal fraction zero is a geometric query result, not a new solver scheduling event. Fresh geometry must not enter the zero-time island branch accidentally. World consumers should reconstruct the event/contact while keeping the original selected fraction; fresh contact position is the actual advanced pivot.

## Local cloning and door context

`/root/russias-army/shared/originalPlayerPhysics.ts:111` clones contacts into and out of its one-entry sweep memo. Explicitly transfer private registration in `copySweepContact` after producing the same detached public values. Both the stored clone and reuse clone need registration. Plain object spreading elsewhere can also lose it; current Game's fixed `sweepOriginalConvex(...,false)` returns the scene hit directly (`/root/russias-army/src/game.ts:2989`). Its dynamic player replacement should remain unregistered. Audit all local spread/clone sites before claiming shared coverage. Arbitrary `structuredClone`, capture JSON and network objects intentionally lose private registration and return unsupported.

Scene triangles and their world vertices are immutable snapshots. DoorWorld changes its movement snapshot when a closed door is opened, reset or authoritative states are replaced. It never rotates an opening panel's physical rigid body: movement removes that panel immediately (`/root/russias-army/shared/originalDoorWorld.ts:95`, `:133`); visible transformed panels are ray-only. Existing Game world stepping is synchronous and its contact callback increments a counter, so ordinary mid-event door mutation is not observed. A general public environment callback can nevertheless change DoorWorld state during a step; the design should cover that explicitly.

A minimal facade wrapper at `OriginalDoorWorld.sweepConvex` can add a private active-feature check to the scene registration: fixed-model features remain valid in the immutable fixed snapshot, while a selected door model remains eligible only while its current `opened` entry is `null`. Opening that specific door then returns known-absent `null` even if the old scene object remains reachable. Reopening/resetting closed membership does not change its authored closed physical vertices. Deletion of another door must not reject an unchanged fixed or closed selected feature. This uses private selected model identity without exposing it publicly. A blanket snapshot-identity failure is too coarse, while blindly refining a stale closed-door snapshot is wrong after that selected body is deleted. If a future movement layer transforms rather than deletes bodies, it needs a separate explicit context contract; this design does not infer one.

## World and standalone consumers

Extend the existing exact quaternion capture at `/root/russias-army/shared/originalPlayerPhysics.ts:317` to positive selected angular fixed events. Compare exact components with `Object.is`; do not rely on regenerated hull identity because the shared-reference hull cache can be evicted. If orientation did not change, preserve the translated query, retaining the proven zero-T roundoff guard. If orientation changed, use dynamic refinement for dynamic pairs and the private selected-feature refiner for registered fixed events. Null means continue after existing elapsed-time accounting; search the unconsumed interval under the existing 48-event cap. Unsupported means current compatibility behavior. A genuine result replaces actual geometric response data while retaining event time/fraction. Do not alter support/handler multipliers, force constants, angular interval or tolerances.

`/root/russias-army/shared/originalExplosives.ts:133` is an independent consumer. Its angular standalone substep must perform the same registered-fixed/changed-orientation check after advance at `:146` and before response at `:148`. Recompute oriented convex from actual angular state before refinement. Keep original selected fraction/event time and recompute normal and manifold data from the refreshed hit; the existing local `const contact`/`normal` bindings will need careful restructuring. Null continues with already-consumed time; no `.85`, hit flag, onContact callback or separation. Unknown custom and dynamic `contact.body` paths remain compatible unless independently supported. Standalone gravity/substep scheduling and the once-per-call actor counter remain unchanged.

This shared registration mechanism avoids requiring every Game/server environment to add another method. It also prevents fixture hooks from being treated as recovered fixed features. A direct recovered scene sweep works in standalone and joint world; a callback that constructs an unrelated replacement contact does not accidentally inherit identity.

## Required validation before release

1. Direct finite triangle registration: rotated false candidate refines null; a genuine face contact, rounded edge/vertex contact and adjacent coplanar support refresh finite current witnesses at unchanged T. Verify selected-feature identity when another triangle is closer or the first all-touching result differs.
2. Metadata cloning: original returned hit, memo stored clone and repeated memo reuse all refine the same exact feature. Public keys/serialized diagnostic values remain unchanged. Unknown and serialized contacts return unsupported.
3. Exact unchanged-orientation controls: preserve the existing zero-T RPG regression, nonidentity quaternions, and shared-reference cache eviction cases without fixture T or solver tolerance changes. A spinning candidate must not bypass the guard.
4. Actual observer seeds: retain genuine Woodland7 and quiet Barrack0 barrel contacts/support; eliminate response/notification at the 51 absent actual poses without asserting that the entire revised trajectory has identical contact counts. Requery can generate later genuine events. Check source `.85` per genuine notification and unchanged actor fuse counters.
5. Bounded time/cost proof: retain every body's integrated substep time, remaining time, false-candidate retries, angular queries and cap hits over the seven seeds, then the relevant complete retained captures. Repeated microscopic candidates must not consume 48 events while discarding significant time. Do not discard a whole interval after a rejected candidate or enlarge cap/sampling allowances. Compare the corrected instrumented copy to corrected production with recursive same-engine `Object.is`, while old final276 baseline remains separately matched to its historical captures.
6. Door context: genuine closed selected door survives unrelated door opening; opening the selected door makes its old registered feature absent; fixed floor feature remains valid. Reset/reconcile and facade forks do not confuse independent closed memberships. Test actual authored finite door geometry, not only a synthetic infinite plane.
7. Standalone and fallback: a false registered spinning fixed candidate causes no impulse/damping/hit/onContact/separation; genuine registered contact preserves source handler behavior; no-contact full time and generic unsupported fixtures remain compatible. Existing standalone tests, world/support/island tests, affected server use and strict types must pass.

Coordinate same-engine/browser and heavy CPU validation with the parent before running it. Preserve the existing final276 observer proof unchanged, save a prepatch source copy/hash and use new correction proof names. A correction may improve geometric fidelity while worsening assisted-jump height; retain strict `>2` acceptance and all original source forces. Native rotational CCD, Havok notification cadence and independent original-runtime parity remain unproved.
