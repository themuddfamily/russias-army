# Actual angular pose validity before dynamic contact dispatch

The default shared world now revalidates positive-TOI dynamic contacts when actual angular orientation changes across the advance, before response, support signals or grenade handlers. This addresses the nine geometrically absent contacts demonstrated in [the point-response audit](ORIGINAL_POSITIVE_TOI_POINT_RESPONSE_AUDIT.md). A translated hull is a candidate prediction when orientation changes; an absent contact on the real rotated hull no longer dispatches `.85` damping. Genuine changed-orientation contacts use the actual pose's normal, witnesses and penetration depth. Unchanged orientations retain their valid translated sweep, as the subsequent roundoff correction below establishes.

This is a physical consistency correction, not an assisted-jump height workaround. No source force, mass, restitution/friction coefficient, grenade lifetime, handler multiplier, five-degree/half-contact-distance rotational interval bound, 48-iteration world cap, 128-iteration constraint cap, solver tolerance or strict greater-than-two-unit jump criterion changed. No original runtime was executed. Native Havok equivalence remains unproved.

## Installed boundary

The initial implementation and its `44fd68…` proof described here are retained as historical evidence. The subsequent exact-orientation guard below qualifies the current dispatch boundary without changing their recorded results.

`shared/originalPlayerPhysics.ts` adds `refineAngularPairAtPose`. For a selected positive-time dynamic pair involving an angular hull, the world first advances all bodies by the candidate's elapsed physical time. It then queries the current full oriented shapes at stationary endpoints under the same total contact distance. Convex/sphere and convex/convex pairs retain their existing finite-feature query and patch methods. A valid contact replaces the stale candidate's normal, witnesses and physical penetration with actual-pose values before the existing response/dispatch path.

An absent actual contact continues the remaining motion search without response, support signal, separation, or grenade notification. The elapsed movement is retained; the remainder is neither discarded nor advanced blindly. The existing event/iteration cap still applies. There is no per-pair notification throttle or rule that all separating/zero-impulse native contacts should be suppressed.

Rotating future candidates at tiny positive fractions also no longer establish current support merely because their fraction is at most `1e−8`. Existing exact-zero contacts retain their support latch; a validated future selected event can latch support through the normal signal path. Translation-only compatibility behavior is retained.

The fix applies to **dynamic pairs involving angular hulls**. Angular hull contacts against fixed terrain/doors still use their existing sampled sweep and response path: identifying and revalidating the same finite fixed feature is a separate remaining requirement. This change does not claim complete rotational CCD, continuous actor scheduling, native notification grouping, or reliable online freshness.

## Subsequent T=0 roundoff correction and guarded default

The broader run exposed an existing RPG/movable regression under configured `contactDistance=0`. Its initial angular velocity was zero. The valid translated SAT selected fraction `1.1102230246251556e−15` in substep 2, at physical time approximately `.010000000000000005`; after advancement the strict stationary SAT saw a positive axis gap of only `5.551115123125783e−17` and returned null. Repeating that unchanged-orientation candidate exhausted the iteration cap without progressing the RPG. This is floating-point translation roundoff, not evidence for increasing T or changing the fixture.

The current default captures the selected pair's exact quaternion components before advancement, only for positive-time angular dynamic candidates. It compares them afterward using `Object.is`. If all angular orientations are unchanged, it retains the already valid translated sweep and existing response path. If orientation changes, actual-pose refinement still applies. The comparison uses quaternion values rather than hull object identity because the angular hull cache retains only one orientation per reference hull; another body sharing that reference can evict it and regenerate an unchanged body's hull object.

This guard adds no tolerance, contact margin, native rest-gap assumption or notification limit. It preserves the existing T=0 translated boundary while retaining rejection of the proven geometrically absent rotating candidates. `originalPlayerPhysics-before-zero-t-orientation-guard.ts.txt` preserves the preguard default exactly, including the `44fd68…` hash; the earlier proof files were not overwritten.

Two additional regression cases restore a translated RPG with a nonidentity, zero-spin orientation against a T=0 movable target. One includes a distant angular body sharing the RPG's reference hull at a different orientation, exercising cache eviction. Both retain the genuine contact, transfer target momentum and set RPG hit. The unchanged existing `shared/originalMovableBody.test.ts` RPG fixture now passes as well. Focused validation passes **85 tests across six files**: five actual-TOI tests, eight movable-body tests, eleven island-world tests, four angular integration tests, eighteen player physics tests and thirty-nine Game player tests. Client TypeScript also passes. The later small allocation guard limits quaternion snapshots to the positive-TOI branch; final broad checks cover that final source independently.
