# Recovered source weapon input and empty-slot selection

Static decoded scripts from Barrack2011 and Woodland2015 are the evidence; no Director executable or VM was run. Both `director-script-extraction/{edition}/casts/parents/ParentScript 6 - weaponry.ls` scripts run `gun` before `choosegun` each actor callback.

`checkweapon` (Woodland345–353, Barrack352–360) accepts a slot if either its chamber or reserve is positive. Failed numeric selection does not change the current slot. A reload with both counts zero clears the current selection to VOID, then scans pistol, SPAS12, AK47, RG6, RPG, Dragunov and returns before loading, sound or a new wait (Woodland116–125, Barrack119–128). A reserve-only earlier slot wins over a later loaded slot. An entirely depleted player remains unarmed; held fire cannot authorize a stale-slot shot. Both pickup scripts52–65 restore VOID selection to the picked weapon before reloading it.

The shared slot-order helpers, client WeaponState and source MatchRoom now implement that eligibility and fallback. The network uses optional `loadout.unarmed` because the existing equipped enum also caches a model/transport identity; the flag carries VOID semantics and authority refuses unarmed shots. The flag survives reconnect. A pickup restores selection only when unarmed; otherwise it preserves selection. Client selection rejects unusable slots before triggering presentation/network synchronization.

Held R is polled before the firing gate (Woodland143–154, Barrack145–166). Woodland resets waitgun to30 on every successful reload callback. Barrack moves poldwaitgun twenty frames beyond waitgun on each reload; the selected weapon's cadence then determines release readiness. Repeated reloads can therefore keep a full chamber locked indefinitely while R is held. The client polls held R at nominal30Hz, sends each accepted reload to authority and restarts its source presentation. Releasing R permits the counter gate to become ready. A press entirely between polling callbacks may be missed, as expected from sampled rather than edge input. Chat suppresses held R, firing and numeric selection; pause, dead players and archived Winter do not invoke this source callback path.

`shared/originalWeaponCounter.ts` now preserves waitgun and poldwaitgun for all six source weapons. Woodland decrements before input guards and gates on waitgun<1. Barrack tests the saved pre-increment difference, resets an idle difference strictly above twice the newly selected weapon's wait, and otherwise increments when the difference is at most that wait. Barrack starts at the initial RG6 wait10/pold0; Woodland starts at wait0. A shot assigns the source counter state rather than imposing an independent elapsed-time cooldown. Selecting a different gun preserves both raw counters and requires its next callback to evaluate the new gate. Successful reload presentation is tracked separately from ordinary firing cadence.

The source client now processes the gun before held numeric selection on each callback. The lowest held Digit1–Digit6 wins, an unusable slot leaves the current selection unchanged, and a usable held slot reapplies its load position even if already selected. Numeric selection is allowed during a reload wait; it preserves ammo, reserve and the shared counters while the new weapon's threshold determines future readiness. Empty held fire attempts reload only at the ready gate. Its empty-slot fallback cannot fire the newly selected slot until the following callback; held R fallback runs before that callback's firing gate. An empty RPG attempts refill at the ready gate without requiring the fire button. A loaded RPG shot resets the Barrack shot counter before its prelaunch reload; Woodland reloads to counter30 before construction and resets to10 afterward. Both overwrite the chamber with the cached count minus one after construction. [The RPG integration](../2026-10-01/ORIGINAL_RPG_COUNTER_INTEGRATION.md) covers the intermediate stages, automatic refill, fallback reload and recovered audio. [Explosive evidence](ORIGINAL_EXPLOSIVE_RULES.md) now documents the installed RG6/RPG callback lifecycles, decoded flight meshes and contact adapter, with native physics and the historical jump still unproved.

Chat callbacks continue advancing the Woodland decrement while freezing Barrack's guarded readiness calculation. The client remembers typing mode for counter advancement outside the direct input callback, including pickup reloads. Authority receives optional transform `typing` and mirrors these guards. Selection and chat transitions flush the current transform before a following weapon request. Optional loadout `sourceCounter` carries validated signed safe-integer waitgun/poldwaitgun plus readiness; reconnect retains the server counter instead of creating a new weapon cooldown.

Manual held-R reload occurs inside the gun callback and completes that callback's counter calculation. Pickup reload occurs outside it: a Barrack pickup therefore needs one additional future callback compared with an otherwise identical manual reload. Offline pause shifts both the callback schedule and counter clock, preserving the remaining wait. Tests cover these state and ordering differences in `shared/originalWeaponCounter.test.ts`, `src/originalWeaponCounterGameplay.test.ts`, and `server/original-weapon-counter.test.ts`.

Remaining timing limits: the client schedules nominal30Hz callbacks and replays at most one second after a rendering stall; the server advances from its own wall clock and caps a single idle replay at256 callbacks. Further Woodland negative idle waits are therefore not an exact unbounded raw-counter trace on authority. Loadouts anchor received counters to client receipt time and do not transmit fractional callback phase. Browser event sampling, transport latency, reconnect and server protection/rewind remain adaptations. These tests establish the installed state transitions, not original Director wall-clock timing or full gameplay equivalence.

All-empty manual-R fallback skips the source HUD/model refresh and can leave stale presentation; empty-fire calls sortweapons afterward and removes models. The copy retains a cached model identity but clears the HUD active row when unarmed. That cleanup, and remote representation of an unarmed cached gun, are not claims of exact original refresh behavior. These limits keep G06/G07 and full presentation parity open.
