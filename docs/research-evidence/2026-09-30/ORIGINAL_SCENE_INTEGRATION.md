# Original scene integration — 30 September 2026

Recovered original Barrack and Woodland scenes now provide the default map rendering and shared gameplay geometry in practice and online modes. The browser and authoritative server load the same packaged source scenes, use the same explicit profile scale and settle the same source spawn anchors against original triangles. This is implemented integration, not evidence that every visual or gameplay detail matches the historical runtime. Winter remains a separate authored map.

## Preserved source packages

Run `python scripts/research/package-original-scenes.py` from the repository root to reproduce [original-scenes](../../../public/assets/original-scenes/). The assembler combines validated decoded positions, normals, faces and raw UVs; original node matrices; resource-named per-part IFX shader bindings; exact decoded cast PNGs; and recovered `explore.buildlevel` overrides. No Director, Lingo or recovered game runtime runs. Missing textures or bindings fail assembly rather than receive substitute assets.

Barrack contains 93 mesh parts, 39,637 vertices and 24,017 faces with 17 texture images. Woodland contains 27 parts, 35,257 vertices and 24,257 faces with 23 texture images. Woodland floor part 0 uses runtime `floortop2`; part 1 retains stored `barerocksand2`. Each edition's `provenance.json` records source, scene and texture hashes. Repeated packaging produced identical artifact hashes and all 40 copied PNGs matched their decoded original inputs byte for byte.

[originalMapAssets.ts](../../../src/originalMapAssets.ts) preloads scene JSON and all textures before Game starts, then registers shared runtime geometry. Failed loads clean up successful partial texture loads and surface initialization failure; default original maps do not silently fall back to the blockouts. The server also loads these packaged scenes before constructing default rooms. Explicit `originalScene:false` remains available for isolated legacy compatibility tests; it is not the default room behavior.

## Shared geometry, player profile and source spawns

[originalMapRuntime.ts](../../../shared/originalMapRuntime.ts) creates one runtime per map from the packaged data. [originalSceneGeometry.ts](../../../shared/originalSceneGeometry.ts) evaluates original parent matrices, applies the proper `(x,y,z) → (x,z,-y)` basis conversion and the shared scale, and retains fixed concave triangle surfaces. Browser and server use its radius-aware support, overlap resolution, swept movement and combat ray queries. Openings are retained instead of being filled with whole-building boxes. Standing contacts require an upward contact normal greater than 0.5, following recovered `goody.hitobj`.

The source player sphere radius is **25**, supported by [Adobe's Using Director 11.5 manual](https://help.adobe.com/en_US/Director/11.5/UsingDirector/director_11.5_help.pdf), printed page 333 / PDF page 344. `makedummy` names its sphere resource `"20"` but never changes its default radius; that name is not a radius measurement. Source `goody.stepFrame` places the eye 60 units above the sphere center, yielding a standing eye height of 85 units above support.

[originalMapProfile.ts](../../../shared/originalMapProfile.ts) uses the explicit adaptation scale `1.72 / 85`, matching the client's 1.72 standing eye height. Radius is `25 × scale`; body height is twice that radius, so the shared capsule representation reduces to the source sphere. This conversion is a client adaptation, not a claim that source units were historical metres. Rendering, collision, map bounds and source spawn conversion all use this profile rather than the authored blockout's map limits.

All six exact `vstarts` position and rotation vectors for each map are preserved in the profile. Original `goody.prepare` initializes the sphere center at `vstart + (4,0,25)` and lets gravity and contact resolution settle it. Joining here is a **grounded adaptation**: preserve that horizontal initialization offset, query radius-aware supported feet below the original initial center, resolve actual triangle penetrations and repeat support/contact resolution until the sphere is clear. A source spawn's Z coordinate is an initialization position, not a terrain height. The resulting settled positions are shared with the authoritative server; failure to find clear support is an initialization error rather than a replacement coordinate guessed on the blockout.

The client applies the stored spawn rotation and uses source world-camera FOV **50** at hip view. All six recovered weapon meshes now share this vertical FOV with the world camera; Dragunov uses the source35-to7.25 progressive zoom. [Primary camera evidence](ORIGINAL_CAMERA_PROJECTION.md) confirms the angle axis. Source viewport/crop and clipping still require comparison.

## Original rendering and material adaptations

[originalScene.ts](../../../src/originalScene.ts) builds indexed source mesh parts directly, preserving their distinct shader assignments rather than the older GLB exporter's merged materials. Local positions and normals remain in source Z-up coordinates; one outer group performs the proper basis conversion and shared uniform scaling. Parent world matrices are evaluated through the same shared helper used for collision. Original raw CLOD UVs remain available as `sourceUv0` and subsequent layers; render UVs use `(u + .5, .5 - v)`, following the pinned W3D runtime adapter. Original texture uploads use `flipY:false` so they do not invert V a second time.

[originalSceneMaterials.ts](../../../src/originalSceneMaterials.ts) installs exact same-named original PNG textures, emissive-style unlit materials, and source explicit double-sided models. Woodland's list is `syccamore`, `spindlybirchleaves`, `rowanbranch`, `othertrees`, `birch` and `outerfencing`; Barrack's list is `outerfencing`. Source reparenting to the created `smokes` group is preserved without moving the models. Alpha planes are retained; no guessed alpha cutoff or added fog/palette is introduced. Materials and generated sky geometry are disposed by their owner; the preloaded shared texture assets remain borrowed.

The source sky is an inward uncapped cylinder with radius `0.95 × floor.boundingSphere.radius`, height 2000, original center `(0,0,1000)` and X rotation 90 degrees. Source texture-transform scale `(.1,1.01,1.01)` is retained as metadata and adapted to UV repeat `(10,1/1.01)` using the pinned player's reciprocal apparent-size convention. Generated Three cylinder UVs are reversed in V only so top vertices sample the source image top and bottom vertices sample its tree horizon. Ordinary original CLOD UVs are unchanged by this generated-primitive correction. The background comes from the original sky bitmap's top-left pixel, RGB `(141,160,174)`.

Both recovered `floortop` images contain complete map aerial textures. The rendering adapter fits source floor object XY bounds across all floor parts to normalized UVs `((x-minX)/rangeX, (maxY-y)/rangeY)`. Its source second-layer noise scale `.005` becomes a tile factor of 200 over the same normalized UVs. Rock part 1 continues to use its original mesh UVs. The normalized bounds fit is corroborated by the pinned player's `world.image` planar branch and the complete-map atlas content; **exact historical planar wrapping and default noise blend remain adapter inferences**. Unweighted multiply follows the pinned adapter's default layer interpretation, not an explicit blend selection recovered from the game's script. Woodland floor part 0 raw UVs span approximately ±0.4993, corroborating whole-atlas use, but they do not exactly equal the simple XY-bounds projection. Texture orientation, projection and color composition still require source comparison before claiming rendering parity.

[originalArena.ts](../../../src/originalArena.ts) installs this rendering and runtime together, removes authored box blockers and fixed pickup placements, and uses original terrain support. Original maps have no authored fixed health/armor/ammo pickups in either the browser arena or default server rooms. Existing weapon drops and their collection logic remain separate gameplay systems; absence of fixed pickups does not mean all source drop behavior is reproduced.

## Remaining original integration work

Fixed-world eligibility follows recovered `worldphysics.setupmodels`: names containing `door`, `baddy` or `barrel` are excluded from fixed bodies because separate source actors handle them. Visibility is not a physics exclusion. The original map geometry and separate closed-door bodies are now active. Original barrel and soldier-actor runtime behavior remains pending.

The [original door animation audit](ORIGINAL_DOOR_ANIMATION.md) recovers 13 Barrack door nodes, their exact modifier/motion bindings and 282 source keyframes; Woodland has no recovered door nodes or motions. Barrack requires source closed-door blockers, authoritative one-way proximity opening, immediate removal of movement collision, distinct recovered visual/raycast trajectories and freezing after the source hold time. Static scene geometry alone does not implement those behaviors.

The [original weapon integration audit](ORIGINAL_WEAPON_INTEGRATION.md) supplies recovered gun meshes, framing and recurrence. Those original meshes and source camera-relative transforms now drive all six default weapon slots; common verticalFOV50 replaces the authored split framing. Viewport/clipping, scope artwork/input and other numerical effects remain incomplete. The [GI rig audit](W3D_RIG_AUDIT.md) preserves 25 source bones, 742 weighted vertices and 796 motion keys, but the source soldier skin and animations are not yet installed. Validated static geometry and shared traversal do not by themselves establish matching weapons, dynamic actors, animation or complete historical gameplay.


### Verified sphere traversal and network paths

The recovered Barrack ramp now has a source-derived complete ascent/descent regression, including rounded sphere support at both floor transitions. Actual Game movement and authoritative validation use those source triangles. Landing recognizes the collision sweep's microscopic positive separation (1e-5 normalization units) and snaps to exact sphere support, preventing gravity accumulation while resting.

The online protocol now optionally carries up to128 actual movement samples per transform, within a64KiB transport envelope. The server checks every sphere segment, grounded/airborne state and total travel; the client queues samples until actual sending and clears obsolete paths after authoritative resets, reconnection or an issued boost. Source-map support tolerance is0.08, matching the client; this and the grounded join are adapter conventions rather than recovered Havok tolerances. Source movement credit retains its initial3-unit allowance, replenishes at14 units/s from server time, and caps at14 for the existing one-second catch-up. Winter retains its3-unit cap. These transport accommodations do not claim original movement speed or gravity.

Original door tracks are now wired into default gameplay through the instance-local shared door world. Movement includes closed source triangles and removes them immediately on opening; combat rays follow each visible animated panel. Only accepted server proximity persists online openings; snapshots/events synchronize both clients and late joins/reconnects. Client/server reset and epoch clocks are separate from solo elapsed time. The recovered sound plays once per opening; joining an already-open room is silent. The [door audit](ORIGINAL_DOOR_ANIMATION.md), [sound provenance](ORIGINAL_DOOR_AUDIO.md) and [verified spawn approach](DEFAULT_BARRACK_DOOR_ROUTE.json) preserve evidence and adaptation limits.
