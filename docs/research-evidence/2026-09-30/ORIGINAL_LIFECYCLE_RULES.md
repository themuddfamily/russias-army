# Preserved lifecycle and scavenging rules: Barrack 2011 and Woodland 2015

2026-10-06 actor-entry correction: [source menu lifecycle](../../../artifacts/fidelity-review/2026-10-06/source-menu-actor-lifecycle/EXECUTION_REPORT.md) removes fresh offline GI creation from source-map constructor/menu return and menu map selection. Both replay handlers reset actor registries before lobby/codename entry; Solo life entry still creates the copy's offline actors. Active playing/paused map changes and Winter menu actors retain their adapters. This does not prove native model deletion, full world reset or historical room-server administration.

Static audit, 2026-09-30. This report uses the preserved publisher scripts decompiled by ProjectorRays; neither Director nor a Lingo VM was executed. The editions are **Barrack 2011-04-15** and **Woodland 2015-06-18**, not an assertion about every historical build. [Extraction provenance](director-script-extraction/provenance.json) records the parser commit, command and file hashes. The earlier [player-report findings](LIFECYCLE_CONTROL_FINDINGS.md) remain separate evidence; the script facts below supersede guesses about these two specific payloads.

All source references below resolve under [Barrack scripts](director-script-extraction/barrack/casts/parents/) or [Woodland scripts](director-script-extraction/woodland/casts/parents/). Line numbers refer to the preserved `.ls` text. A quoted handler is decompiler output, not a measured playback trace. Frame callbacks are not wall-clock seconds.

Collection invokes `weaponry.reload()` on the **currently selected weapon**, even if the collected gun is a different already-owned slot. This matters beyond reserve transfer. Both original reload handlers perform their transfer immediately. Barrack `weaponry.ls:107–135` and Woodland `weaponry.ls:104–132` also lack a positive-needed-ammo guard inside this direct handler: a full chamber can still enter its presentation/lockout path, and a chamber above the reload target can produce negative `vgiven`. In particular the documented Dragunov starts with 30 but its reload target is 28. A pickup-triggered reload is therefore not equivalent to our ordinary guarded reload request. The initial audit recorded that edge case; the implemented follow-up below now explicitly preserves the unusual arithmetic for source maps.

`baddies.bsp` in the drop placement formula is the **remote soldier model's** `boundingSphere[2]*0.75` (`baddies.ls:19–20`), not the local goody constant 50. Its numerical value should come from the preserved soldier model/Director bounds semantics. The drop's position remains a source transform derived from the remote actor's transmitted `pos`; the scripts do not snap it to a terrain support height. The randomized Z rotation is static after death; no spinning, bobbing or pickup ring is defined here.

## Edition differences and bounded absences

Barrack key-code **53** in chat calls `hurt(1000,"Cowardice")` (`goody.ls:239–240`); its walking handler calls `die("Cowardice")` directly (`259–260`). Woodland uses `hurt(1000,"Cowardice")` in both chat (`240–242`) and walking (`264–266`). The scripts establish the numeric key code and death classification; mapping 53 to a browser key is a separate Director key-code compatibility fact. No self-kill score penalty appears in these handlers. Local self-exit leaves the group; it is not a local respawn.

Both health implementations alternate the stored offset in `cheatfinder` (Barrack `goody.ls:192–200`, Woodland `193–201`). Its parity affects the literal death test near zero. Preserve the exact source predicate in evidence, and choose any normalized-health adaptation explicitly rather than describing it as the source's simple zero-health threshold.

No timed spawn protection or invulnerability branch appears in local creation, damage handling, or the recovered gameplay-script corpus for either edition. Damage is applied by `hurt/setlives` without an elapsed-time grace check. This is a bounded absence in recovered **client scripts**, not an independently audited historical relay-server setting.

No frag counter, frag-limit victory check or round countdown/room-wide termination was found in the recovered gameplay scripts. `BehaviorScript 33 - running game.ls:1–3` loops the game frame. The inspected termination is individual death and group departure. This supports the current default single-life room behavior; it does not prove that an unrecovered publisher server could never reset or administer a room.

The generic pickup actor also supports keys, health **+20**, tasks and clues. The inspected `explore.buildlevel` model dispatch instantiates lift/animation/door/barrel actors, not a map-wide health/ammo respawn system. Do not populate the selected original maps with invented fixed pickups merely because generic handlers exist.

## Declared GI bounds adapter and implemented server follow-up

The subsequent authorized server follow-up implements the established source score, pickup quantities, persistent lifetime, camera-space reach, selection preservation and direct reload invocation rules for recovered default scenes. The comparison table above records the pre-fix audit; remaining client presentation, spawn grace and disconnect adaptation gaps are not automatically resolved by that server change. The later control follow-up is described explicitly below.

Both [Barrack GI metadata](w3d-metadata/barrack-baddy.json) and [Woodland GI metadata](w3d-metadata/woodland-baddy.json), lines 182–186, declare a resource bounding sphere centered at zero with radius **1726.8026123046875**. Their input SHA256 values are identical (`c6dfe68c0bd1929c69e2fc8877cadf2f798c104899191a0795bb28821e7e8cc0`). Source `baddies.new` uses uniform **0.045** scale and **0.75** times the model sphere radius; `die` subtracts half that `bsp` from transmitted eye height. The explicit adapter therefore uses:

`source drop offset = 1726.8026123046875 × 0.045 × 0.75 ÷ 2 = 29.1397940826416`

At the existing `1.72/85` normalization, this is **0.5896523037899242** world units below the eye. For a standing player it places the drop **1.1303476962100758** above feet, without terrain snapping. The strict pickup reach remains **50 × 1.72/85 = 1.011764705882353**, so another camera at the same standing height can reach the drop. Static source random rotation is represented as normalized Y-up yaw, ten-degree increments from 10 through 360 degrees.

This is explicitly a **declared-resource-sphere adapter**, not a claim that Director computed precisely that runtime model bound. The Director MX 2004 scripting reference, printed page 670, describes `boundingSphere` as center and radius containing a node and its children. That does not establish unchanged equality to a resource bound after skinning. The preserved GI skeleton decoder reports an error in block 13 ([Barrack validation](w3d-decoded/barrack-baddy/validation.json), [Woodland validation](w3d-decoded/woodland-baddy/validation.json)); an exact animated runtime bound is not established. A rest-mesh AABB-center/max-vertex sphere estimate is about 1249.8412365356178, materially different from the declared bound, and is not substituted silently.

`shared/originalPickupRules.ts` centralizes +30/+5 scores, the six fixed ammo awards, strict camera-distance eligibility, the explicit GI offset, source static yaw and reload arithmetic. Server source reload invocations now accept loaded/no-reserve, full and over-target chambers, restart an active wait, and refund the Dragunov's over-target difference with positive reserve. The later control follow-up now scans source slot order when both stores are empty, chooses the first chamber-or-reserve-positive slot without loading or starting a wait, and carries an explicit unarmed flag if none remains. Pickup restores an unarmed player to its collected slot before reloading. Held R now invokes reload at nominal30Hz while sampled. The client and authority share the per-callback waitgun/poldwaitgun state for all six guns, preserving first-shot and cross-weapon gates. Held numeric selection runs after the gun, allows switching during reload, preserves ammo and counter state, and repeatedly applies the selected load pose. Chat freezes Barrack's guarded calculation while Woodland still decrements; immediate typing/selection transform flushes prevent a following weapon request from overtaking those changes. Optional loadout `sourceCounter` carries raw counters and readiness, retained across reconnect. A manual reload completes its gun callback, while a standalone pickup reload does not: Barrack pickup release needs one extra future callback. Source weapon input runs before pickup collection so the latter does not also consume a duplicate gun callback. [Weapon control evidence](ORIGINAL_WEAPON_CONTROLS.md) records nominal timing, bounded replay, receipt-time phase, empty-slot presentation and explosive-physics limits. Winter and authored fixture pickup/round rules remain independent.

Protocol additions are optional `PlayerSnapshot.score`, `collected.data.score`, `killed.data.killerScore`, and dropped-gun `yaw`. `WeaponDropSnapshot.expiresAt=null` denotes a persistent source pickup; finite Winter/authored deadlines retain their earlier meaning. Scores are authoritative points and remain separate from added frag/death counters. Reconnect preserves these points; repeated collection does not award twice. The existing 128-drop resource cap remains an explicit engineering limit.
