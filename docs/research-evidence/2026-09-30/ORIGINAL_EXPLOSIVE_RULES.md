# Recovered explosive lifecycle and installed callback adapter

The preserved Barrack and Woodland scripts define the same grenade, rocket, explosion and world-physics rules. These are static source observations; neither Director nor its Havok runtime was executed. The copy now uses shared source callback lifecycles in solo gameplay and authoritative source rooms, with explicit collision and movement adapters below.

| Rule | Recovered behavior |
| --- | --- |
| RG6 launch | At `goody.pos`, unmodified `cosine3D(goody.rot)`, velocity1300 source units, mass1, restitution.2, friction.5, zero angular velocity. |
| RG6 lifetime | `howlong=60`, decremented each callback; explodes at `<=1`, on callback59. Collision damps current velocity by.85 and does not detonate. Havok supplies body collision/bounce. |
| RPG launch | Eye plus direction×`goody.bsp` (50 source units), velocity800, mass100, restitution1, default friction0. |

| Explosion | A billboard remains for16 callbacks and applies5 damage each callback at strict local eye distance<250. The script has no distance falloff, obstruction test, special self multiplier or explosion impulse. Damage continues while the player remains in range. |
| Physics clock | Gravity−400 in source Z; each actor callback advances Havok by.05 seconds with10 substeps. |

Source RG6 has no authored aim lift or forward clearance and bounces until callback59; source RPG uses only its50-source-unit muzzle offset, resets velocity each callback and detonates on collision, proximity or callback200. Source blasts persist for16 damaging callbacks and retest current eye positions each time, including the shooter. The shared blast query has no LOS, falloff, self multiplier or impulse. Detonation creates blast state rather than applying an immediate radial damage packet. Archived Winter retains its separate authored rules.

World normalization uses `ORIGINAL_MAP_SCALE=1.72/85`. Each nominal30Hz actor callback integrates .05 physics seconds in ten .005-second substeps, with normalized gravity−400×scale. Multiplying source velocity/gravity by scale and integrating ordinary wall-clock seconds alone would lose that relationship. Both callers use the source callback clock; their scheduling and network prediction remain modern adapters rather than evidence of native runtime timing.

Solo includes the local player sphere; authority includes connected living player spheres. Contact can change player velocity without any detonation boost. Player locomotion, gravity and grounding still use the authored movement controller, so this is not full shared Havok simulation. Friction/restitution coefficient combination, semi-implicit integration, contact persistence, angular response and native convex collision are not proved equivalent.

## Live maneuver failure and next coupling correction

The source-lifecycle browser checks pass for real-server Barrack and Woodland: the recorded static downward shots receive sixteen damage events of five points each, retain blast snapshots and produce no server errors. The separate assisted-jump browser checks fail in both maps and both modes. These tests now listen for contact events, preserve their rise/landing assertions and no longer require the superseded detonation boost. Their two-unit rise threshold was authored for the earlier maneuver test; it is not a recovered source dimension. The failures do not disprove the historical maneuver, but they prevent accepting it in the current copy.

A follow-up static audit identifies concrete missing coupling. `goody.hitobj` sets `jump=0` whenever the player's contact normal has sourceZ>.5, including a grenade underneath; `goody.stepFrame` polls heldSpace in that state and applies impulse`bsp*5=250` at mass1. The current contact handlers always clear grounding, and ordinary jump is an edge action at5.4 with gravity12.5. Normalized source impulse corresponds to7.5882 velocity per wall second and gravity18.2118 under the nominal clock adapter. A downward eye shot initially contacts the top of the player's sphere and transfers downward momentum; upward assistance requires later contact below the player and the source support/jump loop.

Furthermore, the ten projectile substeps update player velocity but keep its center fixed. Original worldphysics advances all rigid bodies together. The next correction needs a shared player-body callback, relative sweeps, joint body-position updates, source gravity/input impulses and body-side support normals before rerunning the historical maneuver. This is an explicit remaining implementation requirement; adding a new detonation boost would contradict the recovered scripts.

[Source player-body rules](ORIGINAL_PLAYER_PHYSICS_RULES.md) detail the shared joint callback, exact impulses, support/heldSpace loop and authoritative input requirements needed next.
