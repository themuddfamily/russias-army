## Adapter correction and interpretation limits

Primary parser: [dirplayer-rs W3D source](https://github.com/igorlira/dirplayer-rs/tree/68376fbb4494a6bbad4c70081ecdcb99814a74c9/vm-rust/src/director/chunks/w3d), pinned commit 68376fbb4494a6bbad4c70081ecdcb99814a74c9. Existing standalone adapter excludes the VM. New `tool-adapter/parser.rs.diff` and `clod_decoder.rs.diff` record changes from that earlier preserved static adapter.

Upstream BONES parser assumes each bone immediately follows the fixed header, causing a bogus 58,112-byte string read at offset 107. In this IFX version 17 block, a record includes an additional 8-byte pair when both bits of any mask 0x09, 0x12 or 0x24 are present. This rule predicts every one of the 25 next-record boundaries without searching ahead or accepting malformed strings. Its exact semantic interpretation remains independently inferred; optional pair values include nonfinite/stale-looking encodings and are preserved as bytes, not used as transforms or constraints. Later U3D schemas have different ordering and must not be applied wholesale.

Upstream CLOD decoder multiplies bone weight magnitudes by its diffuse-color inverse quantizer (1/512), then clamps them; this produced 226 invalid vertices with negative first residual weights. The actual magnitudes reach approximately 16384 and fit the original final quantizer (1/16384). Using that source factor without clamping yields nonnegative weights and exact sums at every vertex. Upstream calls the final factor `spec_iq`; its role for bone weights in old v17 is inferred from the complete encoded dataset. Geometry, hierarchy, bind round-trip and animation are numerically consistent, but primary documentation of these old optional fields/quantizer naming and visual comparison remain desirable before claiming complete runtime parity.

Additional primary-source comparison: [Intel U3D source](https://github.com/ningfei/u3d/tree/5c141d9f0d366357e2b7cf93af2eade284a334be), specifically `CIFXAuthorCLODDecoder.cpp`, `CIFXBoneWeightsModifierDecoder.cpp`, and `IFXSkeleton.h`. That later decoder stores parent names and attributes in a different order and a separate bone-weight modifier quantizer. It supports the weighted-skeleton interpretation but does not establish the older binary layout. LibreShockwave master fca530f9ef388d7ff38fa6c7117feae5bb5411c6 was inspected read-only; its current C++ tree supplied no additional W3D bone parser.

## Original gameplay use of this clip

Already preserved original decompilation, `ParentScript 8 - baddies.ls`: GI scale is .045; automatic bonesPlayer playRate is zero. Each movement update increments `bon` by `speed.magnitude * 10`, wraps above 1000 ms, and samples currentTime=bon. Thus locomotion uses the first 0–1 second of the original clip, rather than looping its entire 3.333 seconds. Death sets currentTime=3000 ms. `ParentScript 9 - fadeaway.ls` increments bon by 8 and samples 2400+bon until bon>600: death portion 2.4–3.0 seconds. Therefore later sampled poses lying down are expected source behavior.

Original remote gun orientation reads bonesPlayer.bone[23].worldTransform (Director is one-based: recovered bone index22, rightfingers), copies position/rotation, self-rotates (0,170,10) and self-translates (0,-3,0). Runtime model transform scale and position remain separate from native original coordinates.

## Exact material/style bindings available

Every new `geometry.json` additionally exports `resources[].shader_bindings[]` with original style `name` and `mesh_bindings[]` indexed by mesh part, plus `nodes[].source_style` joined from the independent raw metadata parser. This preserves the source association omitted from the earlier GLB. Examples: Woodland woodenshed style woodenshed binds part0 to woodenshed; GI style GI binds part0 to 20 - Default. The default style is an alternate source binding, not necessarily the rendered runtime style. Source scripts may replace shader lists/textures at initialization, as recorded in earlier metadata observations. Map GLBs are still the upstream material export; consumers should use the explicit sidecar resource/style bindings instead of assuming DefaultShader is authoritative.

`w3d-rig-audit/manifest.json` records all derivative hashes; `rig-validation.json` records CPU checks. Original raw DCR/XMED provenance remains in payload, Director-extraction and W3D metadata manifests.

## Implemented original GI presentation

[originalSoldier.ts](../../../src/originalSoldier.ts) now builds the preserved 742-vertex, 832-triangle skin with all 25 original bones and original influence indices/weights. Bone local positions are the recovered displacement plus the parent length along local X; inverse bind matrices derive from that hierarchy. Normals stay decoded source normals, and centered CLOD UVs convert once to `u+0.5, 0.5-v`, with texture flip disabled. No anatomy, equipment, replacement weights, IK poses or reduced-detail substitute was added. A requested distance tier retains the full source mesh. Actor names are stored without inventing an in-world billboard.

The assets under [original-soldier](../../../public/assets/original-soldier/provenance.json) preserve decoded geometry/rig-motion data equal in both builds and byte-identical decoded GI texture. [package-original-soldier.py](../../../scripts/research/package-original-soldier.py) verifies that equality before packaging and records raw and canonical hashes. Shared geometry/material resources borrow their textures; actor disposal owns only actor objects and its skeleton, so another actor cannot lose shared assets.

Original model scale `.045` combines with the explicit copy unit adapter `1.72/85`. Alive visual origin is 55 source units above the caller's feet, without recentering original geometry. Native Z-up basis and native Z rotation−90 map original +X facing to the caller's local +Z. The lowest unanimated source vertex consequently lies about 0.0244 normalized units above feet. The original editor node translation is preserved in data but is overwritten by the gameplay script and is not applied to the actor.

Locomotion interprets `speed` correctly as original per-frame position delta: normalized caller speed times delta divided by unit scale, then multiplied by 10, advances the source millisecond counter. Original `shoot` assigns `bon=2000`; the next nominal source step subtracts 1000 **once** when the value is strictly greater than 1000. A stationary first step therefore samples 1000 and remains there until positive movement advances it; it is not silently reduced to zero by modulo arithmetic. Slow adapter frames split into nominal steps no longer than 1/30 second, with a one-second stall bound. This 30 Hz wall-time adaptation is explicit, not proof of every historical engine frame rate.

Held guns use original bone 22 (`rightfingers`) world position/rotation, discard GI scale, then self-rotate `(0,170,10)` and self-translate `(0,-3,0)`. They are siblings of the skin, so `.045` does not shrink them. The module caches the previous rendered bone world pose and orients the gun before the next body transform/currentTime sample, following `baddies.stepFrame` ordering. Original crossed muzzle meshes retain their shot-world pose; no skeletal flinch clip is invented. A source-geometry-derived muzzle convenience point supports existing caller effects; it is not a recovered named socket.

Death now follows `fadeaway.ls` rather than an opacity fade. The model starts at the source eye position 85 units above feet, advances `bon` by 8 per nominal 30 Hz frame, sinks by `-bsp * bon / 300`, samples `2400+bon`, and is removed when `bon>600`. The explicit resource-radius adapter is `1726.8026123046875 * .045 * .75`; in normalized units this is 1.17930460758. It is a resource-radius interpretation, not an executed Director `boundingSphere` query.

Numerical checks of the implemented Three skin found maximum frame-zero **position-vector distance** 0.00125798366 original units over all 742 vertices, below the unit gate 0.002. At death `bon=600`, sampled time is 3000, root height −0.63860921516, and the skin remains visible; at the next nominal step `bon=608`, sampled time 3008, it is hidden. Material opacity stays 1 throughout. All six held slots preserve world scale `(1,1,1)` while the GI uses its source model scale. Eight module tests plus two remote adapter tests passed, including original influence arrays/rest skin, real motion, fire counter, previous-frame gun pose, source sinking/removal/reset and resource ownership.

The static-parser optional-field and inverse-quantizer interpretation limits above remain. Position/scale interpolation is linear; quaternion interpolation uses normalized shortest-path slerp, a WebGL adaptation whose exact Director behavior is not established. `prepareMovie` sets GI runtime standard-shader emissive `(200,200,200)` and specular black; the current unlit texture tint is an approximation of that shader, not an exact recovery of Director's light/color arithmetic. GPU/source-image comparison is separate evidence and is recorded by the parent integration work.
